# 1.4 Mapによるデータ管理

前節では、`insert`、`select`、`update`、`delete` の4つの基本操作を実装しました。

これらの処理では、データを保存するための共通の仕組みとして **Map** を利用しています。

本節では、Mapがどのようなデータ構造であり、データベースの内部でどのような役割を果たしているのかを見ていきます。


## Mapとは

Javaの `Map` は、「キー」と「値」の組を管理するデータ構造です。

例えば、

| キー(ID) | 値(Name) |
| ------ | ------- |
| 1      | Alice   |
| 2      | Bob     |
| 3      | Carol   |

というデータは、Mapでは次のように表現できます。

```text
1 → Alice
2 → Bob
3 → Carol
```

本書では、このキーをレコードのID、値をレコードの内容として扱います。

プログラムでは、データベース本体を次のように宣言しています。

```java
private Map<Integer, String> db;
```

そして、コンストラクタで

```java
db = new HashMap<>();
```

を実行することで、空のデータベースを作成しています。


## なぜHashMapを使うのか

Mapにはさまざまな実装がありますが、本書では `HashMap` を採用しています。

その理由は、指定したキーに対応するデータを高速に検索できるためです。

例えば、

```text
db > select 2
```

を実行すると、

```java
db.get(2);
```

によってIDが2のデータを取得できます。

データ数が増えても、キーを指定した検索は効率的に行えるため、小規模なデータベースの実装には適しています。

なお、本章ではMapの内部構造までは扱いません。重要なのは、「キーを指定すると対応する値を取得できる」という特徴です。


## CRUD操作とMap

前節で実装した4つの操作は、すべてMapの基本操作に対応しています。

| データベース操作 | Mapの操作          |
| -------- | --------------- |
| insert   | `putIfAbsent()` |
| select   | `get()`         |
| update   | `put()`         |
| delete   | `remove()`      |

例えば、

```text
db > insert 1 Alice
```

を実行すると、

```java
db.putIfAbsent(1, "Alice");
```

が呼び出されます。

すると、Mapの内容は

```text
1 → Alice
```

となります。

続いて、

```text
db > insert 2 Bob
```

を実行すると、

```text
1 → Alice
2 → Bob
```

となります。

このように、Mapはデータベース本体として機能しています。


## データの取得

登録したデータは、キーを指定して取得できます。

例えば、

```text
db > select 2
```

では、

```java
db.get(2);
```

が実行されます。

Mapの内部では、キーが2の要素を探し、

```text
Bob
```

を返します。

一方、

```text
db > select 10
```

のように存在しないキーを指定した場合は、

```java
db.containsKey(id)
```

で存在確認を行い、

```text
Record not found.
```

と表示します。


## データの更新

更新処理では、

```text
db > update 2 Robert
```

のような入力に対して、

```java
db.put(2, "Robert");
```

を実行します。

Mapでは、同じキーに新しい値を登録すると、古い値が新しい値で置き換えられます。

その結果、

更新前

```text
2 → Bob
```

だったデータは、

更新後

```text
2 → Robert
```

となります。


## データの削除

削除処理では、

```text
db > delete 1
```

に対して、

```java
db.remove(1);
```

を実行します。

すると、

削除前

```text
1 → Alice
2 → Robert
```

だったMapは、

削除後

```text
2 → Robert
```

となります。

これで不要になったレコードをデータベースから取り除くことができます。


## メモリ上で管理しているということ

ここまでで、データベースとして最低限の機能は完成しました。

しかし、このデータベースには大きな問題があります。

データはすべて `HashMap` の中に保存されています。

つまり、

```text
プログラム
      │
      ▼
 HashMap
```

という構造になっており、データはメモリ上にしか存在しません。

そのため、

```text
db > insert 1 Alice
Inserted.

db > exit
Bye!
```

とプログラムを終了すると、`HashMap` も同時に破棄されます。

再びプログラムを起動すると、新しい空の `HashMap` が作成されるため、

```text
db > select
```

を実行しても、登録したデータは表示されません。

これは、現在のデータベースが**メモリ内データベース**として動作しているためです。


## この節のまとめ

本節では、データベース本体として `HashMap` を利用し、CRUD操作がMapの基本操作によって実現されていることを説明しました。

処理の流れをまとめると、次のようになります。

```text
            ユーザー
               │
               ▼
      insert / select
      update / delete
               │
               ▼
          HashMap
               │
               ▼
          メモリ上に保存
```

この実装はシンプルで理解しやすく、小規模なデータベースとしては十分に機能します。しかし、データはメモリ上にしか存在しないため、プログラムを終了するとすべて失われてしまいます。

次節では、この問題を実際に確認し、データをファイルへ保存する必要性について考えていきます。
